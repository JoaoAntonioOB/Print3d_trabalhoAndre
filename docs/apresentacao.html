O app nunca acessa o banco nem as APIs externas: a API valida, aplica as regras, grava e consulta os serviços de fora.

Esta é a arquitetura BFF, Backend For Frontend. O aplicativo só conversa com a nossa API. A API aplica as regras de negócio, grava no PostgreSQL e consulta as APIs externas, a ViaCEP e a BrasilAPI. O app não acessa o banco e nem os serviços externos diretamente. Isso protege os dados e deixa as regras num lugar só. O esquema do banco é versionado com Flyway.

Integração com APIs externas

CEP e CNPJ preenchem o cadastro sozinhos

SituaçãoResposta da APIO que o usuário vê
CEP/CNPJ válido200Endereço e dados da empresa preenchidos
Malformado ou dígito verificador errado400"CEP inválido" / "CNPJ inválido" (sem chamar o serviço externo)
Não existe404"Não encontrado, preencha manualmente."
Serviço fora do ar, limite ou timeout503"Serviço indisponível, preencha manualmente."

Nunca bloqueia o cadastro. Timeout de 3 s (CEP) e 4 s (CNPJ), com cache em memória. Os testes usam HTTP simulado.

Temos duas integrações externas. Ao digitar o CEP, o app chama a nossa API, que consulta a ViaCEP e devolve só o endereço. Ao digitar o CNPJ, a API valida os dígitos verificadores antes de consultar a BrasilAPI. Os erros são tratados: formato inválido volta 400, inexistente 404 e serviço fora do ar 503, sempre com mensagem clara. E o ponto principal: uma falha externa nunca impede o cadastro, o usuário pode preencher à mão. Nos testes, o HTTP é simulado, nunca chamamos o serviço real.
Esse slide mostra "tratamento de erros e mensagens claras", item do enunciado. Na demo, mostre o CEP 99999-999 (inexistente).
Regras de negócio na API

O pedido segue um ciclo controlado

Pendente→ Em produção→ Concluído→ Entregue
Cancelado a partir de Pendente ou Em produção:Cancelado

Pedido

  • Valor e peso maiores que zero (até 2 casas)
  • Prazo não pode estar no passado ao criar
  • Só abertos podem ser editados

Cliente

  • Nome obrigatório; e-mail e telefone válidos
  • CPF/CNPJ único
  • Não é excluído se tiver pedidos (erro 409)
As regras de negócio ficam na API, não no aplicativo. O pedido nasce Pendente e só pode seguir o ciclo: Pendente, Em produção, Concluído e Entregue. Pode ser cancelado enquanto está Pendente ou Em produção. Pedido entregue ou cancelado não pode mais ser editado. Do lado do cliente, não é possível excluir quem tem pedidos: a API devolve um conflito, 409, com mensagem explicando. O aplicativo também só mostra os botões das transições válidas.
Boa frase: "a regra mora na API; o app só reflete". Se perguntarem por quê: qualquer cliente que usar a API terá as mesmas regras.

Perguntas que a banca pode fazer

Por que usar uma API BFF em vez de o app falar direto com o banco?

O app nunca deve ter credenciais do banco. A API centraliza regras, validações e segurança, e serve dados já prontos para a tela (o painel vem de uma só chamada). Qualquer outro cliente, como um site, reaproveitaria as mesmas regras.

Por que o app não chama a ViaCEP diretamente?

Para validar o formato, aplicar timeout e cache, tratar os erros de forma padronizada e não depender do serviço externo dentro do app. Se trocarmos de provedor, só a API muda.

O que acontece se a ViaCEP ou a BrasilAPI cair?

A API devolve 503 com a mensagem "serviço indisponível, preencha manualmente", e o usuário completa o cadastro à mão. A falha externa nunca bloqueia o cadastro.

Como os dados e a senha são protegidos?

Senha com BCrypt, token JWT assinado e guardado no armazenamento seguro do celular, rotas protegidas, nada de dados de clientes nos logs e segredos só em variáveis de ambiente.

Como vocês garantem que as regras funcionam?

Com 45 testes automatizados: as transições de status, os clientes das APIs externas (HTTP simulado) e fluxos completos contra um PostgreSQL real.

Por que Flyway nas migrations?

Porque o esquema do banco fica versionado e reproduzível: qualquer pessoa sobe o banco do zero e chega ao mesmo estado, inclusive com os dados de demonstração.

Como o faturamento do mês é calculado?

Soma dos valores dos pedidos criados no mês, sem os cancelados. É uma definição simples, documentada na própria tela.

O que vocês fariam com mais tempo?

Hospedagem com HTTPS, renovação de token, perfis de acesso, aviso de pedidos atrasados e exportação de relatórios.
